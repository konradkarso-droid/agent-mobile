## СТАТУС РЕАЛИЗАЦИИ (обновлено 2026-08-24)

Этот документ описывает, **как должен быть устроен новый код**. Часть описанного здесь
ещё не существует в репозитории. Это записано явно, потому что документ, выдающий цель
за факт, опаснее отсутствующего документа: по нему принимают решения, считая, что
опора уже есть.

Проверено чтением кода на 2026-08-24:

- **Слой L4 (RUNTIME) не существует.** Нет ни `AgentService`, ни `AgentRuntime`,
  ни `AgentState`. `MainActivity` сама создаёт `TrustedMediator`, `DeviceSafetyWatchdog`,
  `LlmEngine`, `TermuxKotlinCompiler`, `KotlinCodingTask`, держит `isToteRunning` полем
  Activity и запускает всё в `lifecycleScope`. Раздел 2 и раздел 4 целиком — **цель**,
  а не текущее состояние.
- **`ToolRegistry` не используется.** Инструмент передаётся в задачу напрямую,
  `ActionRequest` строится в самом инструменте. Раздел 3.2 — **цель**.
- **`EmergencyStop` — реален** (правка 2026-08-24): проверяется первой строкой
  `ActionGate.evaluate()`, взводится кнопкой в UI, причина видна на экране, флаг сам
  не сбрасывается. Соответствующий пункт раздела 5 выполнен.

Правило на время переходного периода: **новый код пишется по этому документу, но
подключается через существующие пути**, а не делает вид, что отсутствующий слой уже
есть. Появление настоящего L4 — отдельная задача, а не побочный эффект чужой правки.

## 0. ЧТО ЭТО ЗА СИСТЕМА

Автономный ИИ-агент, работающий полностью на устройстве Android (Kotlin, квантованная
LLM 1.5–3B через JNI/llama.cpp). Ограниченные ресурсы — не временное неудобство, а
постоянное условие проектирования. Приоритеты, в этом порядке:

1. Физическая безопасность устройства (тепло, батарея) — выше всего.
2. Целостность памяти и аудита — данные и след действий нельзя терять молча.
3. Полезность агента.

Никогда не переставляй эти приоритеты местами ради удобства реализации.

## 1. КАРТА СЛОЁВ

```
L5  UI          MainActivity, фрагменты, binding
                ↑ только подписывается на StateFlow, ничего не создаёт и не владеет

L4  RUNTIME     AgentService (foreground), AgentRuntime
                ↑ единственный владелец жизненного цикла и всех singleton'ов

L3  ORCHESTRA   ToteEngine, AgentTask, ToolRegistry
                ↑ доменно-нейтральная механика цикла

L2  CAPABILITY  LlmGateway, Tool (компилятор, OCR, …), MemoryStore
                ↑ конкретные умения, каждое за интерфейсом

L1  SAFETY      ActionGate, DeviceSafetyWatchdog, EmergencyStop, EnergyBudget
                ↑ контуры ограничений, не знают ни о задачах, ни о UI

L0  DATA        Room: Sticker, ActionEvidence, LastStableSnapshot, DAO, Prism
```

**Правило зависимостей.** Модуль уровня N импортирует только уровни ниже N.
Импорт вверх или вбок между несвязанными модулями одного уровня — запрещён.

**Правило Android-изоляции.** `android.widget`, `android.view`, `androidx.appcompat`,
`*.databinding.*` не встречаются нигде, кроме L5. `android.content.Context` разрешён
только в L4, L2 и L0 — и только как `applicationContext`, никогда как Activity.

**Правило чистоты L1/L3.** ToteEngine, ActionGate, EnergyBudget, Prism, классификаторы,
эвристики — чистый Kotlin без Android-зависимостей. Они должны запускаться в обычном
JVM-юнит-тесте на CI. Если новый код в этих слоях требует Android — значит он попал
не на тот слой.

## 2. ЕДИНСТВЕННОЕ СОСТОЯНИЕ

> **Не реализовано** (см. «Статус реализации»). Раздел описывает целевое устройство;
> сегодня состояние живёт полями `MainActivity`.

Состояние агента существует **в одном месте и в одном виде**:

```kotlin
data class AgentState(
    val phase: AgentPhase,            // IDLE, TESTING, OPERATING, ANSWERING, COOLDOWN, EVACUATED
    val taskId: String?,
    val iteration: Int,
    val energy: Int,                  // из EnergyBudget
    val willZone: WillZone,
    val safetyZone: SafetyZone,       // из DeviceSafetyWatchdog
    val emergencyStopped: Boolean,
    val lastOutcomeSummary: String?
)
```

`AgentRuntime` публикует ровно один `StateFlow<AgentState>`. Всё, что хочет знать,
что сейчас происходит с агентом, — читает его.

Жёстко:

- **Никаких булевых флагов состояния в UI.** `isToteRunning` как поле Activity — запрещено.
  UI выводит своё состояние из `AgentState.phase`, и только из него.
- **Локальные `var` внутри цикла — рабочие переменные, а не источник истины.**
  Любое изменение фазы/итерации/энергии немедленно отражается в `AgentState`.
- **StateFlow — для состояния, SharedFlow — для событий.** Событие («шаг завершён»,
  «сработал барьер») не хранится в StateFlow; состояние не рассылается через SharedFlow.
  Для событий: `MutableSharedFlow(replay = 0, extraBufferCapacity = 64,
  onBufferOverflow = DROP_OLDEST)` — и переполнение обязано логироваться, не молчать.
- **Ни один Flow состояния не создаётся в scope Activity.** Только в scope сервиса.

## 3. КОНТРАКТЫ

Эти интерфейсы — граница между слоями. Их сигнатуры не меняются без явного решения.

### 3.1 LLM — единственная точка входа в нативный движок

```kotlin
enum class StopReason { SAFETY_CRITICAL, HARD_TIMEOUT, CANCELLED, MODEL_ERROR }

sealed class LlmResult {
    data class Ok(val text: String) : LlmResult()
    data class Stopped(val reason: StopReason, val partial: String) : LlmResult()
    data class Failed(val message: String) : LlmResult()
}

interface LlmGateway {
    val isLoaded: Boolean
    suspend fun generate(prompt: String, maxTokens: Int): LlmResult
    fun stream(prompt: String, maxTokens: Int): Flow<GenerationEvent>
}
```

Обязательства реализации:

1. **Один вызов за раз.** Внутри — `Mutex`. Нативный контекст и KV-кэш не реентерабельны;
   два параллельных вызова — неопределённое поведение, а не «медленнее».
2. **Остановка по безопасности возвращается как `Stopped`, никогда как пустой `Ok`.**
   Оборванная генерация не должна быть неотличима от ответа модели.
3. Вызывающий обязан разобрать `Stopped` явно. Записывать `partial` в состояние задачи
   запрещено — модель не должна редактировать код, который она видела не целиком.

### 3.2 Инструменты — единая точка прохода через gate

> **Не реализовано** (см. «Статус реализации»): `ToolRegistry` отсутствует, инструмент
> строит `ActionRequest` сам. Раздел описывает целевое устройство.

```kotlin
sealed class ToolResult {
    data class Ok(val output: String, val meta: Map<String, String> = emptyMap()) : ToolResult()
    data class Failed(val reason: String, val retryable: Boolean) : ToolResult()
    data class Unavailable(val reason: String) : ToolResult()
    data class Denied(val verdict: ActionVerdict) : ToolResult()
}

interface Tool {
    val id: String
    val actionType: ActionType
    val crossesDeviceBoundary: Boolean
    val isReversible: Boolean
    suspend fun execute(input: String): ToolResult
}
```

Жёстко:

- **`Tool.execute()` никогда не вызывает `ActionGate` сам.** Это делает `ToolRegistry.invoke()`
  — единственное место в проекте, где строится `ActionRequest`.
- **`ToolRegistry.invoke()` обязан, в этом порядке:**
  1. проверить `EmergencyStop.isActive()` → `Denied`;
  2. построить `ActionRequest` из **полей Tool'а**, не из аргументов вызова;
  3. `ActionGate.evaluate()`;
  4. **записать `ActionEvidence` — всегда, и на ALLOW, и на DENY** (это не опция);
  5. только потом `execute()`.
- **Ни одно поле `ActionRequest` не может происходить из вывода модели.** Ни прямо,
  ни через строку, ни через meta. Провенанс задаётся кодом, а не текстом.
- Новый инструмент = новый класс `Tool` + одна строка регистрации. Если добавление
  инструмента требует правок в `ToteEngine`, `AgentTask` или UI — архитектура нарушена.

### 3.3 Память — явная запись, ленивое чтение

```kotlin
data class MemoryRecord(
    val content: String,
    val tag: String,
    val source: SourceKind,          // обязателен, без значения по умолчанию
    val confidence: ConfidenceLevel, // обязателен, без значения по умолчанию
    val importance: Importance = Importance.MEDIUM
)

interface MemoryStore {
    suspend fun save(record: MemoryRecord): Long
    suspend fun recall(query: String?, limit: Int): List<Sticker>
    suspend fun pendingReview(): List<Sticker>
}
```

Жёстко:

- **У `source` и `confidence` нет значений по умолчанию.** Всё, что пишет агент о
  собственной работе, — `AGENT_INFERRED`. Значение по умолчанию «как от пользователя»
  — это тихая подмена происхождения.
- **`recall()` не читает таблицу целиком.** Фильтрация и лимит — в SQL, не в Kotlin.
  `dao.getAll()` в горячем пути запрещён.
- **Обновление счётчиков доступа и слоёв — в одной `@Transaction`**, целевым UPDATE
  по id, а не через `@Update` целой строки. Иначе параллельные чтения теряют записи слоёв.
- `Sticker` в идеале неизменяем; мутация полей entity в бизнес-логике — запрещена.
- Классификация слоя не зависит от языка и от подстрок в тексте пользователя.
  Ключевые слова в `Prism.classify()` — временный долг, новый код их не расширяет.

### 3.4 Задача

```kotlin
interface AgentTask<S> {
    val id: String
    val description: String
    fun initialState(): S
    suspend fun test(state: S): StepOutcome
    suspend fun operate(state: S, outcome: StepOutcome): S
    fun budgetVerdict(state: S, outcome: StepOutcome): BudgetVerdict
}
```

`ToteEngine` остаётся доменно-нейтральным навсегда. Он не знает слов «код»,
«компиляция», «промпт», «токен». Всё доменное живёт в реализации `AgentTask`.

## 4. ЖИЗНЕННЫЙ ЦИКЛ (ANDROID)

> **Не реализовано** (см. «Статус реализации»): `AgentService` не существует, владение
> лежит на `MainActivity`, долгие процессы идут в `lifecycleScope`. Раздел описывает
> целевое устройство и является списком того, что предстоит сделать.

- **Агент живёт в `AgentService`** — foreground service с постоянным уведомлением.
  `AgentRuntime`, `LlmGateway`, `DeviceSafetyWatchdog`, `MemoryStore` создаются один раз
  там и нигде больше.
- **Activity ничего не создаёт.** Она биндится к сервису, читает `StateFlow`, шлёт команды.
  Пересоздание Activity (поворот, тема, split-screen) не должно влиять на агента вообще.
- **Ни один долгий процесс не запускается в `lifecycleScope`.** Только в scope сервиса.
- **WakeLock (`PARTIAL_WAKE_LOCK`) берётся на время инференса и отпускается в `finally`.**
  Без исключений: любой `acquire` парен с `release` в `finally`.
- **Отмена кооперативная.** Любой `suspend`-вызов, за которым стоит нативная работа или
  внешний процесс, обязан иметь `finally`, который останавливает эту работу
  (`stopGeneration()`, снятие ожидания результата, освобождение WakeLock).
- **Отмена не достаёт до чужого процесса.** Работа, запущенная в другом приложении
  (например `kotlinc` в Termux), доработает до конца независимо от нашей отмены — мы
  прерываем только собственное ожидание результата. Для действий, которые лишь читают
  или пишут во временную папку, это безобидно; для всего, что выполняет код или меняет
  состояние вне песочницы, нужен собственный механизм остановки на стороне исполнителя.
  Отсутствие такого механизма — причина не строить действие, а не повод строить его без.
- **Периодические задачи (ночной проход памяти, консолидация) — только WorkManager**,
  с constraints `idle + charging`. Из Activity или из живого цикла — никогда.
- **Освобождение модели.** У `LlmGateway` есть `unload()`, и он реально вызывается —
  в `onDestroy` сервиса и при `onTrimMemory(TRIM_MEMORY_COMPLETE)`. Две загруженные
  модели одновременно на 4–8 ГБ устройстве = гарантированный kill процесса.

## 5. КОНТУР БЕЗОПАСНОСТИ

- **Счётчик непрерывного инференса — с подсчётом ссылок.** Вложенный или соседний
  короткий вызов не сбрасывает таймер длинного. Жёсткий потолок, который сбрасывается
  побочным вызовом, — это не потолок.
- **Все разделяемые поля контура безопасности — `@Volatile` или атомарные.**
  Обычный `var`, читаемый из другой корутины, — ошибка, а не стиль.
- **Мягкие сигналы (энергия, интерес, срочность) никогда не сравниваются с жёсткими
  лимитами в одном выражении.** Они не могут ослабить жёсткий лимит ни при каких значениях.
- **Fail-closed по умолчанию.** Неизмеримо, неразобрано, недоступно — значит «отказ»
  или «требует подтверждения», но никогда не «считаем, что нормально».
- **Тихих потерь не бывает.** Отброшенный запрос пользователя, обрезанный промпт,
  потерянный результат внешнего процесса — обязаны попасть в `AgentState` или в лог событий.
  Молчание — худший из возможных исходов барьера.
- **`EmergencyStop` читается в реальном коде**, а не «когда-нибудь». Флаг, который никто
  не проверяет, хуже отсутствующего: он создаёт ложное ощущение защиты.
  *(Выполнено 2026-08-24: проверка стоит первой строкой `ActionGate.evaluate()`, стоп
  взводится кнопкой, причина видна на экране, сам флаг не сбрасывается.)*
- **Барьер не отключается ради железа.** Ни один контур из этого раздела не имеет и не
  получит ветку «на слабом устройстве пропускаем проверку». Барьеры дёшевы — это
  арифметика и чтение датчиков; экономить на них нечего, а сама возможность такой ветки
  и есть тот обход по частям, ради предотвращения которого барьеры существуют.

## 6. КОГДА ПИШЕШЬ НОВЫЙ МОДУЛЬ — ЧЕК-ЛИСТ

1. На каком слое он живёт? Импортирует ли что-то с уровня выше? → переделать.
2. Есть ли у него интерфейс, или это конкретный класс, вшитый в конструктор? → интерфейс.
3. Запускается ли он в JVM-юнит-тесте без устройства? Если нет — Android-часть должна
   быть отделена в тонкую обёртку.
4. Меняет ли он `AgentState`? Если да — через `AgentRuntime`, не напрямую.
5. Ходит ли он в LLM? Через `LlmGateway`, разбирая `Stopped` явно.
6. Делает ли он что-то во внешнем мире? Тогда это `Tool`, и он идёт через `ToolRegistry`.
7. Пишет ли он в память? Тогда `source`/`confidence` заданы явно.
8. Есть ли у него `finally` для отмены?
9. Может ли он потерять данные молча? → добавить сигнал.
10. Добавляет ли он новый порог/коэффициент? Пометь как плейсхолдер и укажи, откуда
    возьмётся калибровка. Не выдумывай «разумное» число молча.
11. **Он обязателен или опционален?** Опциональный модуль (распознавание изображений,
    звука, тяжёлый анализ) подключается через явную точку регистрации и обязан
    корректно отсутствовать. Запрещено: вызывать его напрямую из пути запуска,
    считать его наличие само собой разумеющимся, молча деградировать при его
    отсутствии — отключение всегда объясняется на экране с числами
    («выключено: 4 ГБ ОЗУ, требуется 6»), а не выражается пропавшей кнопкой.
    Причина жёсткости: пока каждый такой модуль выключается снаружи, механизм
    отключения по возможностям железа можно добавить сверху позже; один вшитый в
    путь запуска модуль делает это распутывание дороже всей остальной работы.

## 7. СТИЛЬ И ГРАНИЦЫ

- Один класс — одна ответственность. Если в KDoc приходится перечислять «а ещё он…» —
  это два класса.
- Комментарий объясняет **почему принято решение**, а не что делает строка.
  Решения, принятые явно (а не по умолчанию), помечаются датой.
- Никаких новых внешних зависимостей без явного разрешения. Каждая библиотека —
  это APK, RAM и поверхность атаки на устройстве, где их и так не хватает.
- Файлы отдаются целиком, не диффами.
- Если запрос требует нарушить любой пункт этого документа — **не выполняй его.**
  Напиши, какой пункт мешает и какие есть варианты. Тихий обход правила
  из этого файла — самая дорогая ошибка, которую здесь можно совершить.
